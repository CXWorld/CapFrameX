Client and Service Architecture

One frontend, two separately implemented services. Both expose the same API contract because both build on the same platform-neutral core. Everything that touches hardware, drivers or the game process is written once per platform.

Processes, boundaries and data paths

shared code, identical on both platforms runs elevated platform-specific deliberately absent

Demand: what nobody needs does not run

Lightweight modes are UI configuration

ModeFrontendWhat the service does as a result
Fullall views, the three-column layout of the mockupdepending on the open view: record index, analysis, live data
Capturecompact window: target process, hotkey, duration, live FPS, recent runsframe source and logging sensors; no record index, no analysis
Overlaycompact window: profiles, on/off, accent, modules, previewoverlay stack and exactly the metrics of the active modules
No UIhost not running; tray icon and hotkeys belong to the serviceas above but without CEF processes – the lightest state and the default after autostart

There is no second build and no reduced code path. A mode decides what is shown, and therefore what is demanded.
